# 自动化与定时任务

定时任务是 Manor 的周期性工作引擎：一条自然语言提示词、
一个调度计划、一个执行器。平台调度器每 60 秒滴答一次，
找出到期的任务，并将每个任务派发到 worker 集群。

在侧边栏打开 **Jobs（任务）**，即可查看实体内的所有自动化，
包括上次运行、下次运行、状态以及每个任务的运行历史。

## 一个任务包含什么 {#what-a-job-contains}

| 字段 | 含义 |
| --- | --- |
| 调度计划 | `cron`（按表达式周期执行）、`every`（固定间隔）或 `at`（一次性执行，可选在运行后自动删除）。 |
| 时区 | Cron 表达式按任务的 IANA 时区求值——以墙上时钟时间为准，而非服务器时间。 |
| 提示词 | 执行器接收的自然语言指令（`payload_message`）。 |
| 执行器 | 实际运行的内容——见下文。 |
| 上下文 | 可选的工作区、会话、Agent 和目标关联，确保结果落在正确的位置。 |

Cron 表达式使用标准的 5 个字段（分钟、小时、日、月、星期），
支持 `*`、列表、范围和 `*/N` 步长；星期字段的 `0` 表示周日。

## 可以调度什么 {#what-can-be-scheduled}

| 执行类型 | 触发时发生什么 |
| --- | --- |
| Agent 运行（默认） | 创建一个任务，并让 Agent 针对提示词运行。 |
| 工作流 | 从配置好的定义启动一次[工作流](workflows.md)运行。 |
| 技能 | 运行一个特定的技能。 |
| 目标度量 | 重新度量某个目标的指标。 |
| 工作区运行时任务 | 保持工作区健康的内置任务：strategist 复盘、简报、成果评估、聊天洞察提取。 |

当你创建或编辑一个 Agent 任务时，Manor 会在后台根据你的提示词生成一个
**冻结执行技能**——任务将针对这份稳定的脚本运行，而不是每次都从头
重新解读提示词，从而使重复运行的行为保持一致。

## 可靠性 {#reliability}

- 每次触发都记录在只追加的运行日志中（状态、时长、token
  用量、错误），并关联到它所产生的任务和 Agent 执行——
  点击任务即可检视其运行记录。
- 连续失败次数会被统计并突出显示；任务列表提供
  **attention（需关注）** 过滤器，展示失败中的任务及其最新错误。
- 漏跑检测最多回溯 24 小时，因此 worker 短暂停机后
  不会触发大量补跑。

## Agent 也可以创建调度 {#agents-can-schedule-too}

调度对 Agent 以工具形式开放：在聊天中你可以让 Agent
"每个工作日早上 9 点给我发送未完成任务的摘要"，它会自行创建
这个任务，包括运行必须满足的文件交付契约（例如"生成一份
电子表格"）。

## API 摘要 {#api-summary}

| 端点 | 用途 |
| --- | --- |
| `GET /api/v1/jobs` | 列表，支持 `search`、`status`（`all`/`enabled`/`paused`/`attention`）、`agent_id`、分页与汇总计数 |
| `POST /api/v1/jobs`, `GET/PUT/DELETE /api/v1/jobs/{job_id}` | 管理任务 |
| `POST /api/v1/jobs/{job_id}/toggle` | 启用 / 暂停 |
| `POST /api/v1/jobs/{job_id}/run_now` | 通过正常的 worker 路径立即触发 |
| `GET /api/v1/jobs/{job_id}/runs`, `.../runs/{run_id}` | 运行历史与完整运行详情（任务、Agent 执行、工具时间线） |

调度要求 Celery worker 处于运行状态——参见
[Docker Compose](../docker-compose#the-two-worker-split)。
