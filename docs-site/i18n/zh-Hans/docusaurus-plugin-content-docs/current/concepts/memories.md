# 记忆

记忆是跨会话持续存在的持久化事实。它们由同一个存储支撑，
分为两种作用域：

- **Agent 记忆**——Agent 就特定用户学到的内容：
  事实、偏好、上下文和长期指令。作用域为
  （Agent，用户），因此每个 Agent 都记得自己与每个人
  的独立关系。
- **工作区记忆**——工作区的运营大脑：指导、
  偏好、决策、经验教训和事实，规划层与 strategist 层
  在决定工作区下一步该做什么时会参考它们。

在侧边栏打开 **Memories（记忆）**，即可按 Agent 筛选并浏览、
添加、编辑、归档或删除它们。

## 记忆从哪里来 {#where-memories-come-from}

1. **手动**——你自己撰写。手动条目被视为最
   权威的来源。
2. **会话提取**——由 LLM 对一次会话进行扫描，提取出
   值得记忆的陈述（`POST /api/v1/memories/extract`）。
3. **周期性聊天洞察提取**——一个定时任务扫描工作区
   聊天，提取操作者的偏好、指导和决策。自动
   提取的记忆其置信度上限被压在手动记忆之下，因此它们永远
   不会盖过你明确表达的内容。

## 记忆如何被使用 {#how-memories-are-used}

每条记忆带有重要度（1–10）和置信度（0–1）。当
Agent 运行时，系统会从与当前查询最相关的记忆中组装出一个
有预算限制的上下文块——按 embedding 相似度排序，
重要度作为并列时的裁决依据——并注入到提示词中。置信度超过
阈值的工作区记忆同样会被渲染进
工作区运行时提示词。

记忆可以过期（`expires_at`），也可以归档而不删除——
当你希望它们不再进入提示词但仍保留存档时。

## API 摘要 {#api-summary}

| 端点 | 用途 |
| --- | --- |
| `GET /api/v1/memories` | 列表，可按 Agent、用户和类型筛选 |
| `POST /api/v1/memories`, `PUT/DELETE /api/v1/memories/{id}` | 管理条目 |
| `POST /api/v1/memories/{id}/archive` | 归档而不删除 |
| `POST /api/v1/memories/extract` | 从会话中提取记忆 |
| `GET /api/v1/memories/context` | 调试：查看 Agent 收到的渲染后上下文块 |
