# 技能与工具

工具是可执行的能力。技能是指令包，教会 Agent 在何时以及如何使用这些能力。

## 工具 {#tools}

工具可以读取文件、调用 API、搜索网页、查询知识（RAG）、管理文档和任务、调度定时任务、驱动浏览器会话、生成媒体、在沙箱中运行代码，以及通过 MCP 服务器与已连接的集成交互。

工具访问由以下机制治理：

- Agent 配置（Agent 绑定的工具集）。
- 运行时策略。
- 工作区权限。
- 人工审批（HITL）规则。

有两个搜索类工具值得区分：`search_documents` 按名称和元数据查找文件；`rag` 从文档内部检索内容证据。Agent 会被自动引导到正确的工具，但了解这一区分有助于阅读执行日志。

## 技能 {#skills}

技能是可复用的配方——"如何生成每周摘要"、"如何分流一封客服邮件"——只在相关时才加载到 Agent 的上下文中，保持提示词的聚焦。

一个技能通常包含一个 `SKILL.md` 文件（YAML frontmatter 加指令正文）以及可选的资产或脚本。脚本在[沙箱](../operations/sandbox.md)中执行，而不是在应用进程中。

在侧边栏的**技能**下或通过 API 管理技能：

| 端点 | 用途 |
| --- | --- |
| `GET /api/v1/skills` / `POST /api/v1/skills` | 列表 / 创建 |
| `POST /api/v1/skills/generate` | 从描述生成技能 |
| `POST /api/v1/skills/install-github` | 从 GitHub 仓库安装技能 |

技能还为[自动化](automations.md)提供支持：当你调度一个 Agent 定时任务时，Manor 会将提示词冻结为一个生成的执行技能，使每次运行的行为保持一致。

## 编写好的技能 {#writing-good-skills}

- 清晰地命名使用场景。
- 说明所需的输入。
- 描述工具使用的边界。
- 为常见工作流提供示例。
- 当有更窄的工具可用时，避免宽泛的权限。
