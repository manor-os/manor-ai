# 设备 / 产品 3D 展示（3D product showcase）

适用：实体设备或产品的高端宣传片：3D 主视觉（环绕、光扫、拆解标注）+ 真实使用场景镜头 + 品牌收尾，常用于 B2B 投流与展会大屏。默认：9:16、60s、有配音。

## 结构与节拍
60s 主版参考（样片实测），30s 版是独立重剪（自有镜头表），不是截短：
1. 0–4.6s 钩子：场景镜头 + 一个直观的对比画面（例：三栏三代人三种饮品），文字随台词逐短语出现。
2. 4.6–9.4s 问题：一句点出缺口的话 + 场景镜头。
3. 9.4–17.4s 亮相：转入黑色 3D 空间，白色光刃扫过机身、屏幕点亮、Logo 发光、慢速环绕；再把 3D 机器合成进真实场景画面。
4. 17.4–31s 怎么用：3D 推近操作界面（点按涟漪）→ 场景插入镜头 → 3D 拆解视图（部件飞出 + 跟随标注）→ 3D 微距（如冰块慢落、液体注满）。
5. 31–44.4s 三个使用场景 / 三种产品形态：每个约 4.5s，用液体波浪等擦除转场衔接。
6. 44.4–53.5s 总结 + 情感收尾：3D 合影镜头 → 人物场景镜头。
7. 53.5–60s 品牌落版：品牌背景、Logo 组装、光泽扫过、标语；音乐终止和弦落在落版上。

## 视觉规则
- 色彩取自品牌（样片：品牌红 + 深暖黑 + 不锈钢灰 + 暖金点缀），产品形态色单独定义。
- 9:16 安全区：文字避开 1080×1920 的上 220px、下 400px、右 140px（文字区 x 60–940、y 220–1520），字幕底边固定在 y≈1490。
- 字体：默认 Noto Sans CJK SC / Noto Serif CJK SC（中文）、Lato（英文），或用户提供的品牌字体文件（放进 `assets/`）。
- 3D 承担"高级感"，AI 场景镜头只做短插入：每个 AI 镜头在画面上 0.7–4.5s。
- 3D 模型按用户提供的参考图建模：外形比例、屏幕位置、出料口、Logo 位置与参考一致。
- 拆解标注锚定在部件的屏幕投影坐标上，随镜头移动；标注文字只写用户提供的部件名称。
- 转场：带方向模糊的 whip、暖色闪白（≤ 3 帧）、人物镜头上的漏光；颗粒与暗角带种子。

## 制作路线
1. 读取用户资料：产品参考图、Logo 文件、卖点、品牌广告文案；`product-promotion-video` 提供产品身份与证明约束，餐饮场景同时参考 `restaurant-promotion-video`（两者都是 instructions_only 约束技能）。
2. 列出需要用户提供的规格清单（尺寸、产能、功能、认证等）；用户没提供的一律不写，只用定性文案。
3. 3D：在 `video_edit`（HyperFrames）中实现，渲染状态是 seek 时间的纯函数。Three.js 必须是 Knowledge 中的本地文件，经 `video_edit(operation="push_assets")` 暂存到 `assets/references/…`，并按返回的 `project_path` 原样引用（重名时文件会被改名；不要放进 `assets/vendor/`，该目录不随项目同步、也不计入 `review_sha256`；沙箱只预置 GSAP，不能从 CDN 加载）；没有可用的 Three.js 文件时，改用 CSS 3D transform + 分层 PNG / SVG 做伪 3D 环绕与拆解。
4. 场景镜头：用户提供实拍优先；否则 `plan_video_segments` → `generate_video`（图生视频，参考真实产品图）→ `wait_media_jobs`；每个镜头 `render_frame_samples` 取首、中、尾三帧核对产品身份（这些是已完成的 MP4）。
5. Logo 从用户文件重绘为 SVG；品牌背景可用用户素材或 `generate_image`（标注为生成）。
6. 配音：`generate_file(kind="audio")`（purpose 为 narration）→ `normalize_audio_loudness`（−16 LUFS）；品牌名先试读，用 `transcribe_video` 回听确认读音可辨，必要时在 TTS 输入里用拼读写法。中英双版只换文字层、字幕和配音，画面共享。
7. 音乐与音效：`search_free_music` → `import_free_music`，音乐结尾和弦对齐品牌落版；冰块、倒水、点击音效用 `generate_file(kind="audio")`（purpose 为 sfx）。每条 stem 先 `normalize_audio_loudness`（音乐 −22、音效按需），再 `video_edit(operation="push_assets")`，单位增益放置。
8. 审阅：`video_edit(operation="review", snapshot_times=[...])` 取每段首帧与落版；批准后只用返回的 `review_sha256` 渲染。

## 已知坑
- AI 镜头把真实设备画错（例：画成平板电脑而不是机器的屏幕，或 Logo 拼写变形）：每个镜头核对首、中、尾三帧，不对就重生成或改用 3D / 文字叠加。
- 720p 生成镜头放大到 1080p 发软：只在画面上停留很短（≤ 4.5s），并让 3D 与排版承担主画面。
- 风格化 3D 液体看起来像一串珠子：液体用连续的表面或真实微距镜头，不用粒子球堆。
- 编造规格、速度、节省成本或 ROI：只写用户提供并可证实的。
- 生成的配音把品牌名读错或中文不清：必须回听转写确认。

## 验收清单
- [ ] `probe_media`：1080×1920、30fps，时长与 CANVAS 一致；30s 版有独立镜头表。
- [ ] 目视判断每个 AI 场景镜头的首、中、尾三帧：产品外形与 Logo 与参考图一致。
- [ ] 每个 AI 镜头在成片中的持续时长 ≤ 4.5s（对照时间线）。
- [ ] 目视判断成片各段首帧（`render_frame_samples`）：文字都在 x 60–940、y 220–1520 内。
- [ ] 同一组帧与 `transcribe_video` 中出现的规格、数字都能在用户资料中找到。
- [ ] 最后一帧是品牌落版：Logo 与用户文件一致，标语与用户提供的一致。
- [ ] `transcribe_video`：品牌名被转写为可辨认的写法，台词与文稿一致。
- [ ] `analyze_audio`：配音 stem −16 ±1 LUFS；成片 MP4 整合响度在 −20 到 −14 LUFS，true peak ≤ −1 dBTP。
