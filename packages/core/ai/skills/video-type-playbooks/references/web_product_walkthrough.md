# 网页产品录屏讲解（Web product walkthrough）

适用：用户给一个网址，在用户配对的 Chrome 中录屏，再配讲解与字幕，做成网页产品讲解视频。默认：16:9、60s、有配音。

## 结构与节拍
本类型交给 Product Video Studio 的 create-product-video 流程执行，阶段由该流程控制：
1. 发现（discovering）：读取网址与用户说明，列出要展示的页面与操作路径。
2. 计划待批（awaiting_plan_approval）：给出讲解脚本、分段（每段对应一个页面状态与一个动作）和预计时长，等待用户批准。
3. 录屏（capturing）：计划获批后，才在用户配对的 Chrome 中按计划录制。
4. 制作（producing）：配音、字幕、放大、点击高亮、片头片尾。
5. 质检（quality_gate）→ 待验收（awaiting_acceptance）→ 完成。
节奏参考：开场 0–5s 说明产品是什么 → 3–5 个功能段，每段 8–15s，"动作 → 结果 → 价值" → 结尾 5s 网址与行动号召。

## 视觉规则
- 录屏保持真实：不修改页面内容，不伪造数据或界面状态；演示数据用用户提供的测试账号或公开页面。
- 跟随放大到操作区域（1.5–2 倍），点击处有涟漪高亮；等待加载加速并标注。
- 敏感信息（邮箱、令牌、客户数据）在成片中打码。
- 字幕在底部清晰区域（1080p y 880–1060），不压住操作区域。
- 片尾网址与录制的网址一致。

## 制作路线
1. 需要的输入：产品网址（必填）；要展示的功能或页面清单；目标受众与语言；是否需要登录——需要时由用户在配对的 Chrome 中自行登录，agent 不输入密码；不可录制的页面或数据（需要打码的内容）；期望时长（默认 60s）。
2. 只有用户批准计划后才录屏；录屏使用用户配对的 Chrome，Chrome 未配对或不可用时，阶段标记为 blocked 并告诉用户需要做什么，不改用其他方式抓取。
3. 讲解配音、字幕与合成由 Product Video Studio 流程内的 agent 与技能完成；本 playbook 不替它选择工具或跳过它的阶段。
4. 本 playbook 只提供结构与验收要求；不在 Video Studio 的其他类型流程里自行录屏。
5. 成片 MP4 用 `probe_media`、`render_frame_samples`、`transcribe_video`、`analyze_audio` 复核后交付用户验收。

## 已知坑
- 未经批准就开始录屏：录屏必须在计划获批之后。
- 登录墙：未登录时录到的是登录页；先请用户登录，再录。
- 页面在录制期间变化（弹窗、Cookie 横幅、A/B 实验），录到计划外的界面；Cookie 横幅选择最隐私的选项关闭。
- 讲解内容与实际页面不符（功能名称、按钮文案不同）：讲解以录到的页面为准。
- 录到敏感信息且未打码。

## 验收清单
- [ ] `probe_media`：1920×1080、30fps，时长在计划范围内。
- [ ] 项目阶段记录中，计划批准早于首个录屏文件。
- [ ] 成片每个功能段取一帧（`render_frame_samples`）：页面与计划中的页面状态一致，可见点击高亮或放大。
- [ ] 目视判断同一组帧：没有未打码的敏感信息，没有登录页（除非计划包含登录流程）。
- [ ] `transcribe_video` 文本与讲解脚本一致，提到的按钮与功能名称在对应帧中可见。
- [ ] 字幕 `validate_subtitles` 通过。
- [ ] 最后一帧网址与用户提供的网址一致。
- [ ] `analyze_audio`（成片 MP4）：整合响度在 −20 到 −14 LUFS，true peak ≤ −1 dBTP。
