# 前后 / 对比视频（Before / after）

适用：左右或上下分屏，把两个版本（改造前后、剪辑前后、两个模型、两种方案）放在同样的时间轴上对比，配标签与实测数据。默认：16:9、40s、无配音。

## 结构与节拍
1. 0–4s 标题：对比的是什么（例："同一个提示词，两个模型"），首帧可读。
2. 4–10s 条件：展示双方相同的输入或条件（提示词、原始素材、参数），让观众相信是公平对比。
3. 10–30s 分屏同步播放：两侧从同一时刻开始、同一速度播放；中途可对两侧做完全相同的推镜（例：同样的 2 倍中心裁切）以便看清细节。
4. 30–36s 实测数据：每项指标一组并排柱或数字（例：耗时、token 数、代码行数、费用），计数落定在实测值。
5. 36–40s 收尾卡：说明数据来源与测量日期，不下结论，静止 ≥ 1.5s。

## 视觉规则
- 两侧时间完全一致：同一 t 对应两侧同一进度；任何缩放、裁切、调色两侧相同。
- 标签：每侧上方固定标签（名称或"前 / 后"），中间一个"vs"徽章；标签字号 ≥ 32px（1080p），字体默认 Noto Sans CJK SC / Lato，或用户提供的字体文件。
- 分隔线 2–4px，居中；两侧画面尺寸完全相同。
- 只放实测事实：不打分、不写"胜出"、不加主观评语。某一方输出失败就如实展示失败（例：空响应面板 + 原始返回的末尾文字），不修改任何一方的原始输出。
- 数据柱从 0 基线生长，单位写在数字旁，两侧同一刻度。
- 竖版（上下分屏）时文字避开 1080×1920 的上 220px、下 400px、右 140px。

## 制作路线
1. 素材：用户提供两侧视频或可复现的产出；`probe_media` 两侧的时长、帧率、分辨率。
2. 指标：只用用户提供或实际测得的数据，在 CANVAS 写数据表（指标、A 值、B 值、单位、测量方法、日期）。
3. 对齐：首选在 `video_edit`（HyperFrames）中把两侧作为两个视频图层，设相同的起点、时长和速度；或者分别裁切——`merge_videos` 会把多个 clip 首尾拼接，所以每一侧单独调用一次、每次只放一个 clip（同样的长度与速度，传素材本身的 `aspect_ratio`）。在 CANVAS 记录两侧的源入出点。
4. 在 Video Edit 中做分屏、标签、vs 徽章、同步推镜和数据柱；两侧的变换写成同一个函数作用于两个容器；全部是 paused timeline 上 t 的纯函数。
5. 音乐床（可选，轻）：`search_free_music` → `import_free_music` → `normalize_audio_loudness`（例：−20 LUFS）→ `video_edit(operation="push_assets")`，单位增益放置；两侧原声通常静音以免混在一起。
6. 审阅：`video_edit(operation="review", snapshot_times=[...])` 取 3 个分屏时刻和数据落定时刻；批准后只用返回的 `review_sha256` 渲染。

## 已知坑
- 两侧不同步：一侧晚几帧或速度不同，对比失去意义。
- 把两侧放进同一次 `merge_videos` 调用：得到的是前后拼接的一条视频，不是两条对齐的素材。
- 只对一侧推镜或调色，等于暗中偏袒。
- 加入评分、"胜者"、主观形容词，或把失败的一侧"修好"再展示。
- 两侧数据柱刻度不同，视觉上放大差异。

## 验收清单
- [ ] `probe_media`：分辨率、帧率、时长与 CANVAS 一致。
- [ ] 目视判断成片 3 个分屏时刻（`render_frame_samples`）：两侧画面尺寸相同，标签与 vs 徽章可见。
- [ ] 同一组帧中两侧的进度一致（对照 CANVAS 的源时间，偏差 ≤ 1 帧）。
- [ ] 目视判断推镜时刻：两侧缩放比例与裁切中心相同。
- [ ] 数据落定帧的每个数字与 CANVAS 数据表一致，单位可见。
- [ ] 同一组帧中没有分数、"胜出"、"更好"等结论性文字。
- [ ] 收尾卡含数据来源与测量日期。
- [ ] `analyze_audio`：成片 MP4 true peak ≤ −1 dBTP，无计划外的原声串入（静音区间与 CANVAS 一致）。
