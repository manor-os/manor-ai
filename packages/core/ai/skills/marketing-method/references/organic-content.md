# Organic content and community

Use when the audience has recurring questions, useful evidence exists, and the business can sustain creation/responding. Start from buyer questions and the conversion journey, not an arbitrary posting quota. Select a platform from `marketing-platform`; this method describes the editorial mechanism.

1. Define one audience problem or occasion, one editorial promise, and one proof source.
2. Build 2–3 content pillars only when there are enough real examples. Useful patterns: explain a workflow, show a real demonstration, answer a comparison question, document a service/process, or address an objection.
3. For each asset, specify hook/title, one point, proof, media, CTA, response path, and reuse potential. The full draft must be native to each requested platform.
4. Choose a cadence from production capacity and response ability. A calendar is a commitment only if the user requested scheduling and the needed assets/account exist.
5. Review qualified comments, saves, searches, visits, leads, or bookings. Record which buyer question the asset answered; revise the angle based on response quality, not raw reach alone.

Product example: show the real task and UI result, then lead to a trial/demo. Restaurant example: show an actual dish or occasion and give a valid visit/reservation path. Do not manufacture customer experiences, engagement, or trending status. For community posting, check the specific community rules before promotion.

Deliverable when requested: a compact editorial brief, distinct angle bank, finished platform-native drafts, asset list, response guidance, and a realistic measurement sheet.
