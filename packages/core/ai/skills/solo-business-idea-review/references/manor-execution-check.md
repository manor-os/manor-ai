# Manor Execution Check

Use this check when the user asks whether their idea can run end-to-end in
Manor AI or when the review is launched from Manor's built-in validation entry.
This is an execution-fit assessment, not demand validation.

## Classify the core paid outcome

- **Manor-native** — current Chat, Knowledge, Agents, Tasks, file generation,
  Flows, Automations, and optional ready Integrations can produce and deliver
  the core customer outcome.
- **Manor-orchestrated** — Manor can research, build, test, document, launch,
  and operate much of the business, but a customer-facing runtime or platform
  deployment remains external.
- **External core** — specialized production, licensed content, regulated
  judgment, or human expert delivery outside Manor is central to the outcome.

## Map the workflow

Show the concrete sequence:

1. Evidence collection
2. Test artifact
3. Representative buyer test
4. Paid delivery
5. Recurring operation and quality control

For each stage, name the Manor surface or Tool, prerequisite, human approval,
artifact, and verification signal. Name the first external boundary and a
fallback. If the current deployment does not expose a required capability,
downgrade the classification rather than assuming it exists.

Do not count payment processing, a connected customer channel, or public
hosting as Manor-native unless the current deployment actually exposes a ready
Integration for it. Never treat execution fit as proof that buyers care.
