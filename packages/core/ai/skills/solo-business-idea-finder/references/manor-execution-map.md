# Manor Execution Map

Use this reference only when the user asks whether an idea can be built,
validated, delivered, or operated in Manor AI. The classification describes
the current core delivery path, not business viability.

## Classification

- **Manor-native** — Manor can produce and deliver the core paid outcome with
  its current Chat, Knowledge, Agents, Tasks, document/file generation, Flows,
  Automations, and optional ready Integrations. A connected channel or payment
  provider may still be needed, but the value-producing workflow stays in Manor.
- **Manor-orchestrated** — Manor can research, design, build, test, document,
  launch, and operate much of the business, but the customer-facing product
  runtime or marketplace deployment remains outside Manor.
- **External core** — Manor can research, validate, plan, and support the work,
  but a specialized external production capability, licensed content, or human
  expert delivery is central to the paid outcome.

All 18 starters can run through an evidence-review and validation workflow in
Manor. Eight can currently deliver their core outcome Manor-native, seven are
Manor-orchestrated, and three have an external core.

## Use rules

1. Never treat `Manor-native` as proof of demand or profitability. It only
   means the core value workflow can be executed with current Manor surfaces.
2. State prerequisites such as a ready Integration, rights-cleared source
   material, representative buyer access, or human review.
3. For a detailed candidate brief, show the sequence:
   `Evidence → Test artifact → Buyer test → Delivery → Recurring operation`.
4. Name the first external boundary and the fallback if it is unavailable.
5. If current product capability differs from this reference, downgrade the
   classification and explain why; never upgrade it by assumption.
