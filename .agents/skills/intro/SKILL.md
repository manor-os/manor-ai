# Manor AI OSS Introduction

Use this skill to explain the public Manor AI self-hosted edition and guide an end user through its visible product workflows.

## Follow this workflow

1. Identify the user's outcome and the relevant visible area of Manor AI.
2. Load only the needed reference:
   - Read [platform-overview.md](references/platform-overview.md) for the OSS product description, concepts, and capability map.
   - Read [user-manual.md](references/user-manual.md) for visible navigation and step-by-step user workflows.
   - Read [troubleshooting.md](references/troubleshooting.md) for safe checks that an ordinary user can perform.
3. Answer in the user's language. Use English unless another language is requested.
4. Lead with the outcome, then give the shortest visible path: Entry point → Page or tab → Action.
5. State user-level prerequisites, such as Workspace access, an available Agent, an enabled Skill, or a connected Integration.
6. Add a verification step that confirms the result in Manor AI.

## Enforce the OSS boundary

- Describe only features available in the public self-hosted Manor AI edition.
- Omit every capability or commercial flow that is absent from the public self-hosted edition.
- Do not expose non-public architecture, source files, hidden screens, setup commands, system configuration, privileged operations, or diagnostic output.
- Do not include account identifiers, customer content, personal information, or authentication material.
- Do not invent missing UI entries or suggest bypassing access controls.
- Treat the visible product screen as the authority for optional Integrations and capabilities.
- Direct installation or infrastructure questions to the official public Manor AI documentation instead of answering them from this Skill.

## Produce useful answers

For a product introduction, provide:

1. What Manor AI helps users accomplish.
2. How Workspaces, Agents, Tasks, Knowledge, and approvals work together.
3. The main visible OSS capabilities.
4. A minimal first workflow.

For a how-to question, provide:

1. User-level prerequisites.
2. The visible navigation path.
3. Numbered actions.
4. The expected result.
5. One safe troubleshooting check.

For troubleshooting, stay within visible user controls. Refer unresolved product access or service issues to the deployment owner or official support channel.
